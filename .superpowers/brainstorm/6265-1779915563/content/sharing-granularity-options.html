Sharing × Multi-Function: Three Approaches

Scenario: West Elmhurst procures Workday, assigns it to HR + Procurement, and wants to share with Ivy Hatherley — but Ivy Hatherley only wants to share for HR, not Procurement.

Option A: Sharing configured per-function (navigate to each)

Multi-function assignment sets what YOU use. Sharing is configured separately when you click each function in the navigator. No sharing UI appears during multi-function assignment.

  • Each function's sharing is self-contained
  • Clear mental model: navigate → configure
  • No complex nested UI
  • Requires clicking into Procurement separately to share
  • User might forget to configure sharing for assigned functions
  • More clicks for the "share everything" case
Option B: "Also share?" sub-checkbox per assigned function

When you check "Also assign to Procurement" AND sharing is active, a sub-checkbox appears: "Also share for Procurement?" — opt-in per function, inline.

  • Single screen — no navigation required for common case
  • Explicit opt-in per function
  • Clear cause/effect: check "Procurement" → see "share for Procurement?"
  • Nested checkboxes can feel cramped
  • Scaling: 5 functions + 3 successors = many sub-options
  • Mixes two concerns (assignment + sharing) in one section
Option C: Sharing grid (successor × function matrix)

After multi-function assignment, a small grid appears showing which successors share which functions. Compact but dense.
