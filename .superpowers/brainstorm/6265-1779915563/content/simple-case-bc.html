Comparison

Dimension B: Always grid C: Cards → Grid on demand
Learning curve One pattern to learn (grid) Two patterns (cards for simple, grid for complex)
Simple case feel Grid with 1 column feels like overkill — "why is this a table?" Cards feel natural and quick — familiar dropdown pattern
Transition to complex Just add columns — no mode change Clicking "Assign to additional functions" swaps cards → grid (mode change)
Shared service UX Both select same → prompt "Link as shared?" inline in grid "Share with..." toggle is explicit and visible
"Establish shared" discoverability Less obvious — implied by both rows choosing same option Explicit green "Share with..." section — hard to miss
Implementation complexity One component (grid), always rendered Two components (cards + grid), conditional rendering, transition logic
Persona fit Architect-natural; may feel dense for Executive Executive-friendly by default; Architect gets grid when needed
The "shared service" discoverability problem in B: In the grid, if both rows independently select "Xero Finance", is that a shared service or two independent Xero subscriptions? The grid needs an additional mechanism to express this (the "Link as shared service" checkbox shown above). In C, the "Share with..." toggle makes the intent explicit upfront — you can't accidentally create a shared service.
