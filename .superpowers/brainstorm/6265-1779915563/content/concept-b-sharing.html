Concept B Extended: "Share with..." Linking

Each successor picks their system, but after selecting, they can opt to "Share with..." other successors — linking their choices together.

Mechanism: After selecting a system (existing or new), a "Share this with other successors?" toggle appears. Checking a successor links their decision — their row updates to show "Shared: [System] (with [Successor])" and becomes read-only unless unlinked. This expresses intentional coordination within the per-successor model.

Semantic distinction: Shared vs coincidentally-same

Shared service (linked):
Both select "Keep SAP" AND are linked via "Share with..."
→ Generates shared governance obligation
→ Cost split applies
→ Changes propagate between successors
Coincidentally same (unlinked):
Both select "Keep SAP" but NOT linked
→ Each operates SAP independently
→ Implies disaggregation into separate instances
→ No shared governance needed
This distinction resolves an ambiguity in the current tool: if two successors both "choose" the same system, is it shared or disaggregated? The linking mechanism makes the intent explicit.
